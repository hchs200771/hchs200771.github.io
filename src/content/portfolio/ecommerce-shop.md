## 這個專案在解決什麼

我做「海風日常」，是想把小型網店常遇到的四個坑，在設計時就處理好：

- **超賣**：最後一件商品，兩個人同時下單卻都成功
- **重複下單**：網路卡住、連按兩次，變成兩張訂單
- **庫存卡死**：下單不付款，商品一直被佔住
- **資安破口**：密碼、權限、上傳或付款通知沒有檢查好

這是一套從零打造、全站跑在 Cloudflare 的電商系統。**畫面能操作之外，訂單、庫存與付款也要能驗證。**

## 怎麼做出來的

我用 Prompt 指揮 AI，先寫架構規劃，再依里程碑實作會員、商品、購物車、下單與付款。Claude Code 負責規劃與取捨，Codex 負責實作，我負責決定與驗收。

**資安與效能都寫進需求，每個階段都有完成標準。** 實際怎麼下指令，可以讀[我怎麼用 Prompt 做出一個兼顧資安與效能的電商網站](/blog/prompt-ecommerce-security-performance/)。

## 已完成的功能

### 前台

- **逛商品**：首頁橫幅、分類、新品、搜尋與分頁
- **選規格**：顏色與尺寸分開選，色票連動照片，標示售完與剩餘庫存
- **購物車**：訪客可先加入，登入或註冊後合併到會員購物車，顯示免運進度
- **結帳與訂單**：下單即預留庫存，查看明細與付款期限，待付款訂單可自行取消
- **手機操作**：購買按鈕固定在畫面底部

### 後台

- **分類與商品**：管理多規格、價格與照片，圖片上傳至 R2
- **庫存盤點**：查看實際庫存、可售數與待付款預留數
- **訂單管理**：依狀態篩選，查看商品、收件資訊與顧客；訂單詳情已實作付款紀錄顯示，畫面尚待驗收

### 付款

- **綠界信用卡**：已在綠界測試環境走完「刷卡 → 付款通知 → 訂單已付款」
- **付款回跳**：顧客回到訂單頁查看結果，付款狀態以伺服器通知與對帳為準

付款實作已完成測試環境驗證，**尚未部署到線上示範站**，也還不是正式收款服務。

## 資安

### 帳號與 Session

- 密碼使用 PBKDF2-SHA256 加隨機鹽值，帳號不存在也跑一次雜湊，減少時間差線索
- Session 是辨認登入狀態的憑證；KV 只存 token 的 SHA-256，不存可直接登入的原始值
- Cookie 設 HttpOnly、Secure、SameSite=Lax；登入與註冊有限流

### 權限

- 後台 API 每次驗證管理員身分，不能只靠畫面擋人
- 查詢別人的訂單回 404，不透露資料是否存在
- 每個請求重新確認帳號狀態，登入後跳轉只接受站內路徑

### 輸入與上傳

- API 輸入用 zod 檢查格式，SQL 查詢參數化，不把輸入直接拼進查詢
- 圖片採格式白名單、上限 5MB，由伺服器產生檔名，不接受可夾帶程式碼的 SVG
- 非預期錯誤只回代碼與追蹤編號，詳細內容留在伺服器日誌

### 金流通知驗證

- 驗證簽章並用常數時間比較，通知金額必須等於資料庫訂單總額
- 重送通知不重複處理，綠界「模擬付款」通知不改資料
- 每 10 分鐘排程對帳，補漏掉的付款通知

## 效能

- 商品頁採 SSR，也就是伺服器先產生內容，方便搜尋引擎讀取；購物車、結帳與訂單頁只在瀏覽器渲染
- 部署後前台透過 Service Binding 內部通道呼叫 API，不經公開網路
- R2 商品圖用 UUID 命名、內容不變，帶一年快取與 `immutable`，更新圖片就換網址
- 每個規格一個 Durable Object 狀態物件，只讓該規格的庫存操作排隊；結帳時各規格平行預留
- 商品與訂單列表分頁，`pageSize` 最大 100；購物車只存規格與數量，價格每次讀最新值

## 訂單與庫存不出錯

- **防超賣**：獨立庫存物件管理每個規格，測試 30 個請求搶 5 件，剛好成功 5 筆
- **防重複下單**：結帳帶冪等鍵，也就是辨認同一次操作的編號，重送只拿到同一張訂單
- **金額由伺服器重算**：不信任瀏覽器送來的價格，建單時保留商品與單價快照
- **逾時釋放**：Workflows 在 30 分鐘後取消未付款訂單；庫存物件另有 35 分鐘的預留到期保護
- **狀態有條件**：只有符合目前狀態才能更新；已取消訂單收到晚到付款時標記待退款處理

## 幕後技術

- **前台**：Nuxt 4（Vue）；**後台**：Vue 3 + Element Plus
- **API**：TypeScript + Hono，部署在 Cloudflare Workers
- **資料**：D1（SQLite）存會員、商品與訂單，KV 存 Session，R2 存圖片
- **庫存與流程**：Durable Objects 管庫存與購物車，Workflows 等付款與處理逾時
- **金流**：PaymentProvider 共同介面隔離廠商差異，目前實作綠界信用卡
- **測試與檢查**：67 個自動化測試跑在本機真實的 Workers 執行環境；GitHub Actions 檢查型別、測試與建置

## 目前進度與接下來

付款已在綠界測試環境驗證，尚未部署到示範站；後台付款紀錄畫面也還需要驗收。接下來依序補上：

- 出貨與退款流程
- 後台 Cloudflare Access 身分驗證，API 入口一起保護
- Turnstile 人機驗證與通知
- 之後再做營運儀表板與 AI 店員

[示範站](https://ecommerce-storefront.ecommerce-api.workers.dev/)目前是付款功能完成前的版本，可以逛商品、加購物車與下單，還不能付款。
